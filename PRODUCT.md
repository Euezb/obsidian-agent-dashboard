# Product

## Register

product

## Users

The primary user is a single Windows desktop Obsidian user who opens the dashboard daily to orient themselves, continue active work, and discover noteworthy AI projects and news without leaving their Vault.

## Product Purpose

Agent Dashboard is a calm command surface inside Obsidian. It puts today's tasks and recently active notes first, shows the Vault's health and note-creation rhythm second, and provides curated GitHub and AI-news discovery third. Codex actions remain explicitly user-triggered tools rather than background automation.

Success means the user can understand what needs attention, reopen relevant notes, assess Vault health, and find worthwhile AI developments within one short scan.

## Brand Personality

Warm, quiet, editorial, and precise. The interface should feel considered and literate while remaining unmistakably a dependable product tool.

## Anti-references

- Dark cyberpunk or terminal-style dashboards.
- Generic SaaS walls where every metric and feed receives an identical card.
- Excessive rounding, wide ghost shadows, glassmorphism, or decorative gradients.
- Loud page-load choreography, parallax, or motion that delays access to information.
- Dense news feeds without hierarchy, summaries, or clear recency.

## Design Principles

1. Lead with today's work: tasks and recent notes receive the strongest hierarchy.
2. Show health as evidence: every score exposes its causes and next actions.
3. Curate discovery: daily and weekly GitHub trends and daily AI news should feel selected, not dumped.
4. Keep Codex intentional: network access, token use, and Vault writes begin only after a clear user action.
5. Let warmth support focus: personality comes from typography, proportion, and restrained color rather than decoration.

## Accessibility & Inclusion

- Meet WCAG AA contrast for text and interactive controls.
- Support complete keyboard navigation and visible focus states.
- Never encode status using color alone.
- Respect `prefers-reduced-motion`; essential state changes remain understandable without animation.
- Keep routine product motion within 150–250 ms and use it only to explain state changes.
